  1. Developer writes code

    Work happens on a branch, locally.

  2. Push to GitHub

    A push or pull request to main sets off the run.

  3. GitHub Actions starts

    The workflow in .github/workflows picks up the event.

  4. Prepare the environment

    Check out the repo, install Node and dependencies.

  5. Scan the code

    Gitleaks looks for secrets, Semgrep for risky code, npm audit for vulnerable packages.

  6. Build the application

    Lint, build the site, package it into an nginx container.

  7. Scan the container

    Trivy checks the image for known CVEs.

  8. Deploy to staging

    The container runs inside the runner as a throwaway test site.

  9. Attack the running app

    OWASP ZAP crawls staging and probes it like an attacker would.

  10. Collect all findings

    Every report is gathered into one bundle.

  11. Security decision

    The gate counts findings against the policy in scripts/security-gate.sh.

Pass: production

The build is published to GitHub Pages. You're looking at it.

Fail: fix issues

Production is blocked and an issue is opened with a link to the findings.
